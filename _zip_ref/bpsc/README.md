# Blood & Plasma Supply Chain (BPSC) — MVP

Платформа для учёта запасов донорской крови, адресного оповещения доноров, прослеживания единиц и перераспределения запасов.

## Запуск
```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m app.seed
uvicorn app.main:app --reload
```
Откройте http://127.0.0.1:8000 (интерфейс) или http://127.0.0.1:8000/docs (API).

| Роль | Вход |
|---|---|
| Администратор | admin@bpsc.kz / Admin12345 |
| Станция | station1@bpsc.kz … station3@bpsc.kz / Staff12345 |
| Больница | hospital1@bpsc.kz … hospital5@bpsc.kz / Staff12345 |
| Донор | donor1@example.kz … donor500@example.kz / Donor12345 |

Для настоящего использования задайте переменные: `BPSC_SECRET` (ключ JWT), `BPSC_KEY` (ключ шифрования AES-256), `BPSC_DB` (путь к базе), `BPSC_CORS` (разрешённые источники). Значения по умолчанию подходят только для демонстрации.

## Что нового
- **Публичная главная страница** (`#/`): запасы по группам крови в реальном времени (`GET /api/public/stats`, только агрегаты), как работает платформа, роли, безопасность.
- **Запись донора на визит**: выбор станции, компонента, даты и времени (слоты по часу, 09:00–16:00, Пн–Сб, по 2 донора на слот, на 30 дней вперёд). Проверяются интервал между донациями, одна активная запись на донора, занятость слота. Если донор отвечает на запрос больницы, запись привязывается к заявке, а уведомление получает статус «принято».
- **Кабинет донора**: обзор («когда можно сдавать снова» по каждому компоненту), запросы, запись на визит, история донаций (что стало с каждой единицей), профиль с определением геолокации.
- **Геолокация**: в регистрации и профиле можно определить координаты браузером или выбрать город; координаты также можно исправить вручную.
- **Станция**: после приёма донация проходит состояния «тестирование → протестирована → хранение». Результат проверки и каждое изменение фиксируются в журнале единицы.
- **Карта**: станции, больницы, открытые заявки и крупные анонимные кластеры доноров (координаты доноров округлены, кластеры менее 3 человек не показываются).
- **Дашборд**: графики запасов по группам крови, прогнозируемой потребности и сроков годности.
- **Отчёт FR-15**: количество закрытых заявок, среднее и медианное время выполнения от создания до завершения.
- **Автосписание**: просроченные единицы автоматически списываются при запуске и затем каждую минуту; ручной запуск также доступен.
- **Живые обновления**: кабинет донора проверяет уведомления раз в 15 секунд, список заявок станции/больницы автоматически обновляется с таким же интервалом.
- **Интерфейс переписан на React** (Vite). Собранная версия лежит в `static/`, поэтому для запуска по-прежнему нужен только Python.

## Разработка интерфейса (нужен Node.js 18+)
Исходники в `frontend/`. Пересобрать интерфейс после правок:
```bash
cd frontend
npm install
npm run build      # результат попадает в ../static
npm run dev        # режим разработки на :5173 с проксированием /api на :8000
```

## Новые эндпоинты
| Метод и путь | Доступ |
|---|---|
| `GET /api/public/stats` | все, без входа (агрегаты) |
| `GET /api/stations`, `GET /api/stations/{id}/slots?day=YYYY-MM-DD` | вход; слоты — донор |
| `POST /api/appointments`, `GET /api/appointments/my`, `POST /api/appointments/{id}/cancel` | донор |
| `GET /api/donors/me/overview` | донор |
| `GET /api/appointments`, `POST /api/appointments/{id}/complete`, `POST /api/appointments/{id}/no-show` | станция (только свои записи) |
| `POST /api/units/{id}/test`, `POST /api/units/{id}/store` | станция (только свои единицы) |
| `GET /api/map` | станция, больница, администратор (обезличенные доноры) |
| `GET /api/reports/summary` | станция, администратор (включая FR-15) |
| `POST /api/maintenance/expire` | станция, больница, администратор (ручное списание; автосписание работает отдельно) |

Часовой пояс слотов: UTC+5 (Астана); меняется переменной `BPSC_TZ_OFFSET`.

## Тесты
```bash
pytest -q
```
Тесты: сценарии T-01…T-13 из документации, проверки RBAC, блокировки входа, цепочки резерв → передача → переливание, тестирование/хранение и списание просроченных, карта и отчёт времени выполнения, а также запись на визит (слоты, вместимость, интервал, ABAC станции, приём донации по записи).

## Структура
- `app/db.py` — схема SQLite, триггеры «только дополнение» для `trace` и `audit`
- `app/security.py` — bcrypt, JWT, шифрование AES-256-GCM
- `app/services.py` — совместимость, подбор доноров, запасы, резерв, прогноз, перераспределение
- `app/main.py` — REST API, RBAC/ABAC, валидация, лимит запросов, аудит
- `app/seed.py` — синтетические данные
- `frontend/` — исходники интерфейса (React + Vite), `static/` — его сборка, которую раздаёт FastAPI
- `tests/` — автотесты

## Ограничения MVP
Уведомления хранятся в базе и показываются через периодическое обновление веб-интерфейса (SMS/push не отправляются); карта схематическая и без внешних картографических тайлов; данные синтетические; нет интеграции с медицинскими системами; SQLite вместо PostgreSQL. Время выполнения FR-15 собирается для заявок, закрытых после обновления схемы БД.
